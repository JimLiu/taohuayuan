# 桃源 · 豁然开朗

《桃花源记》实时三维长卷（three.js）。春日薄雾的清晨，从武陵溪口出发，缘溪行、逢桃林、舍船入山，豁然开朗。

## 打开方式

| 用途 | 做法 |
|---|---|
| **直接看** | 在项目目录运行 `npm run preview`，然后打开 http://localhost:5179/ 。也可以用任意静态服务器提供 `dist/` 文件夹，例如在 `dist/` 里运行 `python3 -m http.server 8000`，再打开 http://localhost:8000/ 。放在网站的子路径下也可以。 |
| 开发 | 先 `npm install`，再 `npm run dev`，然后打开 http://127.0.0.1:5178/ |
| 重新构建 | `npm run build`，输出到 `dist/`。 |
| 重新压缩素材 | `npm run assets`（即 `tools/optimize-assets.sh`），只在改动了 `assets-src/web/` 里的原件后才需要。 |

`dist/` 里只有 `index.html` 和一个 `assets/` 文件夹，发布时把两者一起上传。`assets/` 里的文件名都带内容哈希，可以长期缓存。

不能直接双击 `dist/index.html` 打开：浏览器不允许 file:// 页面加载模块脚本和模型文件。这时页面会停在加载画面，并说明要改用网页服务器打开。

**体积**：`dist/` 共 5.3 MB，以前的单文件版约 11 MB。明细如下：

| 内容 | 大小 | 处理 |
|---|---|---|
| 朗读音频（m4a） | 2.5 MB | 原件是 3.9 MB 的 MP3，转成 AAC（约 80 kbps），时间与原件逐样本对齐 |
| 人物、岩石、蕨类模型（mshz） | 1.3 MB | gzip 压缩，载入时由浏览器解压 |
| 贴图 | 0.8 MB | 颜色贴图和蕨类法线贴图转成 WebP；岩石法线贴图转成 WebP 后反而更大，保留 JPEG |
| 脚本 | 0.9 MB（gzip 后约 265 KB） | three.js 单独成一个文件（550 KB），项目代码 344 KB |
| 页面和样式 | 31 KB | |

素材原件在 `assets-src/web/`（`tex/`、`ref/`、`audio/`），压缩版生成到 `src/assets/`，构建时再由 Vite 复制进 `dist/assets/`。

运行条件：

- 浏览器要支持 WebGL 2（新版 Chrome、Edge、Safari、Firefox 均可）。不支持时，页面会给出说明。
- 模型文件用浏览器自带的 DecompressionStream 解压，需要 Chrome 80、Safari 16.4、Firefox 113 或更新的版本。版本太旧时，页面会给出说明。

调试用的地址参数：

| 参数 | 作用 |
|---|---|
| `?ch=3` | 直接从第 4 幕开始（编号从 0 起算） |
| `?motion=reduce` | 按“减少动态效果”显示 |
| `?nogl` | 模拟不支持 WebGL 的情况 |

## 入口

打开后在桃花林的溪上（夹岸数百步，落英缤纷）。点右下的 **循文入境**（或按 Enter），镜头就会随原文一句一句走完全篇，共 28 幕，朗读默认开启。

不点「循文入境」时，可以自由走动：拖动环顾，WASD 行走。底部的**场景条**按原文次序排着十处景致：缘溪行、桃花林、山有小口、初极狭、豁然开朗、阡陌交通、屋舍俨然、黄发垂髫、美池桑竹、来此绝境。点一处（或按数字键 1–0）即可前往，场景条上方会显示这一处的原文。按 R 或 Esc 回到桃林；走开一段距离后，原文提示会自动收起。

**关于自动播放**：多数浏览器在用户点过页面之前不允许网页出声。如果打开时带了 `?ch=` 直接进入导览，或浏览器拦下了声音，故事会先静音照常进行，并提示“点一下画面或任一按钮”；点过之后，朗读会从当前这句接上。从「循文入境」按钮进入时，这次点击本身就算允许，朗读直接开始。

## 操作

### 导览中

底部是播放器：上面一行是幕次、本幕名称和时间，中间是进度条（每幕一个刻度），下面是上一幕／播放暂停／下一幕，以及目录、朗读开关、「⋯」和退出。

- 暂停／继续：空格
- 上一幕／下一幕：← →
- 跳到任意位置：拖动进度条，或在「目录」里点任意一句
- 退出导览：Esc
- 拖动画面：只在本幕镜头附近小范围环顾，不会退出导览。
- 回正：松手几秒后镜头会自动回正；也可以点「回正」或按 R 立即回正。

### 「⋯」面板

- **节奏**：连贯体验，或逐章慢读（每幕读完停下，点「继续」再往下）。
- **字幕**：原文＋白话、只看原文、只看白话。
- **朗读**：默认开启（也可以点播放器上的「朗读 · 开」或按 V 切换，选择会被记住）。
- **环境声**：默认关闭。
- **画质**：高画质或轻量；手机默认轻量。
- **动态**：可暂停场景里的一切动态。
- 另有重置镜头、保存画面（PNG，不含界面）、隐藏界面（按 H 或点「显示界面」恢复）、操作说明。

### 信步游览（不在导览时）

| 输入方式 | 操作 |
|---|---|
| 鼠标 | 拖动环顾 · 滚轮前后 · 双击某处走过去 · 单击景物看原文 · 点底部场景条换景（场景条放不下时，滚轮可左右滚动） |
| 键盘 | WASD／↑↓ 行走 · ← → 转身 · Shift 快走 · E／空格 升高 · Q／C 降低 · 1–0 切换场景 · R／Esc 回到桃林 |
| 触屏 | 单指环顾 · 双指缩放 · 双击某处走过去 · 轻点景物看原文 |

行走时不会穿过房屋、篱笆、树干、井、草垛、岸石和渔船，也不会钻进地面。能走到的范围只限于溪谷和桃源盆地，看不到场景外侧未完成的背面。

字幕里带下划线的词可以点开释义。点画面中的景物（渔舟、桃花林、小口、良田、美池、屋舍、村口大树等），会弹出对应的原文和简短说明。

## 测试情况（真实浏览器）

### 已测

- 28 幕都能到达。顺序播放和跳转到同一幕时，状态一致：昼夜、船的位置、镜头都对得上。
- 暂停、继续、上一幕、下一幕、拖动进度、目录跳转、逐章慢读的停顿、结尾停留与退出，都正常。
- 导览中拖动环顾有幅度限制，回正正常。
- 朗读播放、跳转后与画面同步，误差约 0.02 秒。音频加载失败时会给出提示，并改为静音继续。
- 朗读默认开启时的自动播放（Chrome 以 `--autoplay-policy=document-user-activation-required` 模拟严格策略，点击为真实鼠标事件）：
  - 点「循文入境」进入，朗读立即开始；
  - 带 `?ch=3` 直接进入、还没点过页面时，声音被拦下，页面给出提示，故事静音照常走；点一下画面后，朗读从当时的位置（约第 29.6 秒）接上，与画面差 0.03 秒；
  - 内置浏览器里真实点击「循文入境」，朗读立即出声。
- 保存画面：解码生成的 PNG 并逐像素抽查，内容正确。测试时没有触发真实下载。
- 隐藏界面后能恢复；画质、动态开关都正常。
- 模拟 WebGL 不可用，以及故意删掉贴图、模型文件时，都有对应提示。
- 构建出的 `dist/` 用三种服务器测过：`npm run preview`、`python3 -m http.server`、一个自写的支持分段请求的小服务器（无头 Chrome，Apple M4 GPU）。结果：
  - 13 个资源都正常返回；
  - 控制台没有报错；
  - 贴图、岩石、蕨类和两个人物都正常显示；
  - 真实点击「循文入境」后，m4a 朗读与画面同步，误差约 0.02 秒；
  - 发布版不再把 three.js 挂到 `window.__t` 上。
- 如果直接双击 `dist/index.html`（file://），页面会停在加载画面，并提示改用网页服务器打开。
- 样式表和脚本都没加载到时（例如开发服务器正在重启），加载画面只剩一个小圆圈和几行文字，不会出现铺满屏幕的黑色圆盘。
- 底部场景条：点选、数字键 1–0、R／Esc 回桃林、退出导览回到桃林，都正常；走开 24 米后原文提示自动收起。
- 在以下尺寸检查过字幕、播放器、场景条、「⋯」弹层互不重叠，弹层也不会超出屏幕：
  - 桌面 1551×1086、1440×900；
  - 手机竖屏 375×812、360×740、390×844；
  - 手机横屏 844×390。

### 未测或有限制

- **触屏**：没有用真机测试。手机布局用的是浏览器的设备模拟。拖动、双指缩放、双击行走是用合成的触点事件验证的。
- **减少动态**：只通过 `?motion=reduce` 测试，没有在系统设置里真正开启。开启后落花和阵风会减弱，界面过渡改为即时；故事本身的镜头运动仍然保留。
- **浏览器范围**：只在 Chromium 内核的浏览器里测过，Safari 和 Firefox 没有实测。
- **python 服务器与 Safari**：`python3 -m http.server` 不支持分段请求（Range），对音频总是整份返回。Chrome 在这种情况下照常播放朗读，也能跳转。Safari 播放媒体通常要求服务器支持分段请求，所以用 Safari 看时建议用 `npm run preview` 或正式的网页服务器。这一点没有在 Safari 上实测。
- **python 服务器偶发加载失败**：有一次在机器满负荷（同时在编码视频）时用 python 服务器打开，一个模型文件连接失败，页面停在加载失败提示；点「重新加载」即可。机器空闲时连续测了 6 次，都正常。`npm run preview` 没有出现过这个问题。
- **朗读对齐**：字幕按朗读音频的时间标注逐句提示，不保证逐字对齐。第 11 幕「平旷」开头约 23 秒是朗读音频里的配乐间奏，这段时间只有画面，没有字幕。
- **碰撞**：竹竿和小件器物不做碰撞。院子的篱笆只能从开着的院门进出。

## 录屏

`docs/video/taohuayuan-xunwenrujing-1080p60.mp4` 是「循文入境」全程的录屏，从片头一直到最后一幕停住。

- 片头 6 秒，第一帧就是标题「《桃花源记》——陶渊明」和「制作：宝玉」，背景是网页首页的桃花林（界面隐藏，落花和水面照常在动）。标题停留约 4.6 秒后淡出，画面淡成纸色，接进第一幕。
- 时长 4 分 17 秒，文件 607 MB（平均约 19 Mbps）。桃花、落英、草地和水面细节多，所以码率偏高。
- 画面：1920×1080，60 帧，H.264（CRF 18）。按 2 倍分辨率渲染后缩小，边缘更平滑。
- 录制方式：页面的时钟由录制脚本逐帧推进，所以每一帧都完整渲染，不会丢帧，也不会因为机器快慢而加速或变慢。
- 声音：用的是朗读原件（MP3），重新编码为 AAC 192 kbps。声音按页面自己记录的故事时间对齐到画面。标题显示的前 5.4 秒没有声音；从片头淡成纸色时起，朗读音频开头的渐入响起，首句「晋太元中」在第 9.5 秒左右。用互相关检查了朗读的第 12 秒和第 200 秒两处，误差都在 0.1 毫秒以内。
- 抽查了六句字幕出现时的画面，字幕和场景都对得上。
- 录屏里的字幕和播放器都是页面本身的界面。
- 录屏用到了参考页面的两个人物模型，所以同样**仅供个人学习**，不宜公开发布。
